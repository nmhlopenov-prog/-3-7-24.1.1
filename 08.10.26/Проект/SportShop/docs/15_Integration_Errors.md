# 15. Ошибки интеграции

## Ошибка №1. Несовместимость форматов данных (размер как число vs строка)

### Какая ошибка была внесена
В интеграционном тесте и в main.py размер товара передавался как число (40),
тогда как в JSON-файле data/products.json ключи размеров хранятся
как строки ("40").

### Как она проявилась
Функция add_to_cart возвращала False с сообщением «Неверный размер»,
так как проверка if size not in product['sizes'] не находила число 40
среди строковых ключей "40", "41", "42".

Тест test_full_cycle падал с ошибкой:
AssertionError: False is not true

Функция create_order возвращала None (корзина пустая), из-за чего
тест test_cart_total_matches_order_total падал с ошибкой:
TypeError: 'NoneType' object is not subscriptable

### Как была исправлена
В файлах tests/test_integration.py и main.py размеры заменены на строки:
add_to_cart(cart, products, 1, '40', 2)
add_to_cart(self.cart, self.products, 2, '41', 3)

### Вывод
JSON всегда хранит ключи объектов как строки. При интеграции модулей
важно следить за типами данных на стыках.


## Ошибка №2. Пустые модули после создания через touch

### Какая ошибка была внесена
Файлы src/*.py создавались командой touch, но код в них
не записывался из-за проблем с копированием блока cat > file << 'EOF'
через буфер обмена (строки вставлялись вперемешку).

### Как она проявилась
ImportError: cannot import name 'get_low_stock' from 'src.catalog'
Все файлы src/*.py имели 0 строк.

### Как была исправлена
Файлы перезаписаны через python3 - << 'PYEOF', который надёжно
записывает содержимое целиком.


## Ошибка №3. Мусорные строки в data/products.json

### Какая ошибка была внесена
При создании data/products.json через cat > ... << 'EOF'
в файл попали служебные строки cat > data/products.json << 'EOF'
и EOF в конце.

### Как она проявилась
JSON-файл становился невалидным, json.load выбрасывал
json.decoder.JSONDecodeError.

### Как была исправлена
Файл перезаписан через Python с json.dump.


## Ошибка №4. Некорректная логика get_low_stock

### Какая ошибка была внесена
Функция get_low_stock суммировала остатки по всем размерам
и сравнивала сумму с порогом. Из-за этого ни один товар
не попадал в список «низкий остаток».

### Как она проявилась
При запуске main.py выводилось:
Товаров с низким остатком: 0

### Как была исправлена
Логика изменена: теперь проверяется, есть ли хотя бы один размер
с остатком <= порога. Возвращаются товары с полем low_sizes,
где перечислены размеры с низким остатком.
